## 데이터 구조 선택 이유 (리스트 & 딕셔너리)  
# 사용한 구조  
리스트(List): 전체 프롬프트 목록을 순서대로 저장  
딕셔너리(Dictionary): 프롬프트 1개의 정보(제목, 내용, 카테고리, 즐겨찾기)를 저장  
# 선택 이유
구조: 리스트	순서 유지  
장점: 딕셔너리	키로 빠른 접근, 항목 구조화 용이  
단점: 전체 순회 용이	특정 항목 검색 시 전체 탐색 필요, 순서 기반 접근 불편  
→ 프롬프트 목록 전체를 순서대로 보여주면서,
각 프롬프트의 세부 정보를 구조적으로 관리하기 위해
리스트 안에 딕셔너리를 담는 구조를 선택했습니다.

## 메인 루프 설계 (while 반복문)  
while True:  
    # 메뉴 출력  
    # 사용자 입력 받기  
    # 입력값에 따라 기능 실행  
    # '0' 입력 시 break → 프로그램 종료  
# 설계 의도
사용자가 종료를 선택할 때까지 프로그램이 계속 실행되어야 하므로 while True 사용  
종료 조건: 사용자가 '0'을 입력하면 break로 루프 탈출  
잘못된 입력이 들어와도 프로그램이 종료되지 않고 다시 메뉴를 출력하도록 설계

## 데이터 영속화 설계 (향후 개선 방향)  
현재 프로그램은 실행 중에만 데이터가 유지되며,
종료 시 데이터가 초기화됩니다.  

# 개선 방안: JSON 파일 저장 방식 제안  
import json  

저장  
with open("prompts.json", "w", encoding="utf-8") as f:  
    json.dump(prompts, f, ensure_ascii=False, indent=2)  

불러오기  
with open("prompts.json", "r", encoding="utf-8") as f:  
    prompts = json.load(f)  

# JSON을 선택한 이유  
형식: JSON	딕셔너리 구조 /	장점: 그대로 저장 가능, 가독성 좋음	단점: 대용량 데이터에 비효율  
형식: CSV	표 / 장점: 형태 데이터에 적합	 단점: 중첩 구조 저장 불편  
→ 현재 데이터 구조(리스트+딕셔너리)와 가장 잘 맞는 JSON 형식이 적합합니다.  


## 충돌 처리 규칙  
# 동명 프롬프트 처리  
같은 제목의 프롬프트가 이미 존재할 경우 추가를 허용합니다.  
제목이 같더라도 내용이 다를 수 있으므로 별개의 항목으로 저장됩니다.  
목록에서 번호로 구분하여 관리합니다.  
# 카테고리 처리 규칙  
카테고리는 지정된 목록 중에서만 선택 가능합니다.  
목록에 없는 카테고리 입력 시 '기타'로 자동 분류됩니다.  
# 즐겨찾기 충돌  
즐겨찾기는 토글 방식으로 동작합니다.  
이미 즐겨찾기된 항목을 다시 선택하면 즐겨찾기 해제됩니다.
